## Summary

Every finding describes behaviour Hypergolic really has. None is false as a whole. The audit's
weak point is classification: it calls 14 things a Hypergolic bug that are spec-silent choices (or
an unmerged amendment), and its severities do not follow one rule.

| CONFIRMED-RECLASSIFIED | 35 |
| REFUTED | 0 |
| UNVERIFIABLE | 0 |

Four sub-claims inside reclassified findings are refuted: "JPEG cannot be uploaded" (UPLOAD-4),
`x-foo` accepted as a fault (CONFIG-6), shell-side query transposition as a bug (INC-2), and
rejecting a schema root without `properties` as a bug (CONFIG-5). No finding is UNVERIFIABLE as a
whole; the parts that need a device are listed under "Not validated".

- **Lowered (17):** CONFIG-1, INTENT-1, CONFIG-3, CONFIG-4, CONFIG-5, CONFIG-6, CONFIG-7, IDENTITY-3, STORAGE-1, STORAGE-5, RESOURCE-2, RESOURCE-3, RESOURCE-4, RESOURCE-5, RESOURCE-7, UPLOAD-1, KEYS-1.

What matters most:

- **RELAY-1 and OUTBOX-1 are both critical.** Napplet ciphertext passes ingress, native admission,
  the approval service and the signer on both paths. Nothing between admission and the signer blocks
  or flags it: the only event check anywhere is a list of three authentication kinds, and the review
  sheet shows the ciphertext as ordinary content under the title `Event kind 4`. The new probe takes
  `outbox.publish` all the way to the relay sender, which removes the audit's reason for rating
  OUTBOX-1 lower.
- **NIP5D-1 stands, and it is not "N/A mobile".** A `MessagePort` crosses a sandboxed srcdoc frame
  in both directions in Chromium and WebKit, and Hypergolic's own Kehto patch already transfers one
  out of the guest in production. Not run on a device.
- **Four medium findings are really high:** NIP5D-2, RELAY-3, INTENT-3 and INTENT-4 each break an
  upstream MUST or MUST NOT.
- **Two high findings are not bugs:** CONFIG-1 (upstream ties the schema to "this source"; scope
  persistence is the model's decision 55) and INTENT-1 (`intent.launch` exists only in open PR #148).
- **The model has defects too:** IDENTITY error results omit the primary field (real), and two
  further points where upstream text sides with Hypergolic against the model (`x-` extensions, schema
  root `properties`).

## How each finding was validated

1. The cited Hypergolic lines were read at `0b00b23e`; corrected lines are in the tables.
2. Each audit probe was read before it was run, to see what it imports and what it stubs. All of
   them import Hypergolic's real modules. Their stand-ins are native ports, sockets, the signer and
   stores, none of which can produce the reported result by itself. Two were too shallow to carry
   their finding alone (`relay/cipher.test.mts` enters below ingress and the native decode;
   `core/ingress.ts` hand-copies the side-lane routing); new probes close both gaps.
3. The same input was run through `napplet-oracle` and the decisive output line recorded.
4. Each finding was attacked: another code path (the patched Kehto, the native layers, later
   checks), a harness artifact, a model decision that permits the behaviour, or a SHOULD or MAY read
   as a MUST.
5. Class and severity were then set by the guide above. One rule was applied throughout: a missed
   reply to a malformed or extended request is medium; a MUST broken on a well-formed request is high.

## Errors in the audit's text

These do not change a verdict by themselves; the tables give the detail.

- **NIP5D-1:** the `MessageChannel` at `dist/index.js:2399-2413` is Hypergolic's patch
  (`runtime/patches/@kehto__shell@0.20.0.patch:350-363`), not Kehto's. The navigated document's
  `theme.get` was "not answered" because the navigation was blocked and the request never sent.
- **OUTBOX-1:** "traced to admission, not to a published event" is now out of date (P-CIPHER).
- **RELAY-1 / OUTBOX-1:** "Expected … the same for NIP-44" cannot be shown with the oracle (M7).
- **CONFIG-1:** the "Spec" line is not upstream text, and the expected value for the probe's
  sequence is `{"theme":"light"}`, not `dark` (O-CONFIG step 10).
- **RELAY-3:** "still advertised at `nap-catalogue.ts:41`" is a description string; the real
  exposure is the binding method (`@kehto/shell` `dist/index.js:1541-1549`).
- **RELAY-6 / OUTBOX-5:** `invalid publication` is the parser's exception text; by the code path the
  wire error for a refused `outbox.publish` template is `approval denied` (not run natively).
- **RESOURCE-4:** "the 5th concurrent request: expected queued". In the model the 5th starts at
  once; only URLs beyond 10 in flight wait.
- **RESOURCE-7:** "defeats the raw-SVG rule" is overstated: the model's own default allowlist
  delivers `text/plain` and `application/octet-stream`, which carry an encoded SVG equally well.
- **UPLOAD-1:** the cancelled result is trace `upload-refused` step 5, not `upload` step 7.
- **UPLOAD-4:** "JPEG cannot be uploaded" is false on the shipped path: a JPEG is accepted and
  re-encoded as a stripped PNG (`UploadTransport.kt:11`, `UploadPhotoPreparation.java:15-50`).
- **INTENT-5:** for its own probe input the oracle's answer is `unsupported convention`, not
  `invoke rejected`.
- **INC-2:** shell-side query transposition is required of the runtime by upstream
  (`NAP-INC.md:104-107`); only where it happens differs from the model (decision 38).
- **KEYS-1:** the upstream quote is not verbatim, and `keys.action` is a MAY (`NAP-KEYS.md:169`).
- **CVM-1:** applies only to `payment: "deny"` or `"allow"`; the default gives the model's string.
- **MEDIA-1:** three strings, not one; native lines are `:97,100`.
- **SRCDOC-1 / Check 4:** the vector split is 25 + 6, not 26 + 5, and the BOM vector is refused even
  after the BOM is stripped (it has no `<html>` tag).
- **Check 7:** the adapter's side-lane routing is a hand copy of `guest-message-receiver.ts:32-45`,
  not the real receiver. A probe on the real receiver agrees with every number.
- **Check 2:** the trace replay shows silence for `nosuch.thing` and `storage.clear` only; the
  claim for unknown `relay.*` and `keys.*` types is true by code, not by that replay.
- **"Not checked", self-target INC `channel.open`:** a harness artifact. The probe's two views share
  `d=caller`, so one peer is found and a review prompt is left unanswered. A true self-target replies
  `peer unavailable` at once.
- **Reproduction:** `storage/register.mjs` registers a scratchpad path that no longer exists, so
  `storage/envelope.test.ts` cannot run as documented (`validation/storage/register.mjs` works).
  `--experimental-strip-types` cannot run `relay/stream.test.mts` (it needs bundling, as the audit
  says), and `relay/cipher.test.mts` and `relay/query.test.mts` resolve `nostr-tools` only from
  inside the Hypergolic tree.
- **Line numbers** are corrected in the tables (for example `guest-message-receiver.ts:21`,
  `published-artifact.ts:114-116`, `verified-artifact.ts:168-223`, `guest-envelope.ts:83-85` for
  THEME-1).
